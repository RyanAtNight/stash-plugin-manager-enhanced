## Completed: responsive search

Installed, Browse, and Configuration now filter after **250 ms without input**. Each new input restarts the delay. The search field stays connected while results refresh, retaining keyboard focus, the cursor, and text selection. Composition input waits until composition ends. Pending work is cancelled on full renders and unmount.

Starting a search also removes an old Installed/Configuration plugin anchor. Otherwise the navigation observer could reveal the previously linked plugin again, reset the search, and steal focus after the results changed.

## Original findings — all resolved

P1 means a correctness issue to prioritize because it can affect the wrong package or lose user edits. P2 means a normal bug fix. P3 means small polish. Reproductions used the real application/service classes with isolated DOM fixtures and mocked service responses; these are not claims that destructive operations were run against the live library.

### 1. P1 — Bulk action counts exclude hidden selections, but operations include them

Select Alpha and Beta, then filter to Alpha. The button displays **Update selected (1)**, but clicking it submits both package IDs. Browse uses the same mismatch for bulk installation. Uninstall also constructs the full selection, although its confirmation names the packages.

The rendered counts come from filtered packages; action handlers collect selected packages from the entire inventory/catalog. Choose one consistent scope for the count, confirmation, and operation. The least surprising fit for the current count is to operate on selected results matching the filters, with an explicit indication if other selections remain hidden.

Evidence: [Installed count](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:777), [Browse count](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:898), [operation selection](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1394).

### 2. P1 — Ordinary redraws discard unsaved settings and collapse configuration panels

Expand a plugin's Configuration panel, edit a numeric setting, then dismiss an existing notification. The field returns to its saved value and the panel closes. Filtering, changing tabs, and saving another plugin also rebuild configuration from the saved inventory. The completed search fix preserves the search field; configuration drafts still need their own state.

Keep drafts and expanded plugin IDs independently of rendered elements. Clear a draft only after a successful save or an explicit discard/reset. This also prevents accidental loss of another plugin's edits while saving the first plugin.

Evidence: [configuration rendering](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1021), [full redraw](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1052).

### 3. P2 — A failed source deletion still removes the source locally

Make `saveSources` reject, then delete a source. An error is shown, but `inventory.sources` is nevertheless replaced with the list excluding that source, and the catalog is cleared. The server still has the source. A later save of the full local source list could unintentionally carry that deletion forward.

Check the boolean returned by `runOperation` before changing local state, and use the successful refreshed/server-returned list. The add/edit handler already checks operation success and provides a useful precedent.

Evidence: [delete-source handler](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1440).

### 4. P2 — Failed configuration saves enter the saved-state cache anyway

Change a stored number from 1 to 17 and make `configurePlugin` reject. The error is reported, but the app assigns 17 to `inventory.pluginConfig` afterward. A subsequent redraw presents the unsaved value as though it came from saved configuration.

Respect the operation result and keep unsuccessful edits in draft state, separate from the last confirmed server values.

Evidence: [configuration save](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1597).

### 5. P2 — Mutating actions can overlap

Hold one `runOperation` promise open. Per-plugin and source mutation buttons remain enabled; a second operation runs immediately. When the second finishes, `busy` becomes false even though the first is still pending. Overlapping complete-source-list writes can overwrite one another; inventory refreshes and status messages can also arrive out of order.

Guard mutation entry points and disable their controls for the entire operation, including dependency preparation. Keep navigation and searching usable. Account for the existing sequential dependency operations when introducing the guard.

Evidence: [per-plugin controls](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:340), [operation lifecycle](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1081).

### 6. P2 — Retry does not retry a failed initial load

Reject the first `loadInstalled` request. The error panel offers Retry, but clicking it calls `mount`, which immediately returns because `#spme-root` already exists. No second request is made.

Give Retry a load path that can reuse the error shell, or explicitly unmount before mounting again. Verify recovery with a rejected first request and successful second request.

Evidence: [mount guard](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:236), [Retry handler](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1345).

### 7. P2 — Optional browser storage failures make healthy sources look broken

Let the source request succeed but make storage `setItem` throw a quota error. `loadAvailable` reports the source as failed and discards all returned packages. If the fallback `getItem` also throws, the whole catalog promise rejects.

Keep storage caching in a separate guarded block. Source health should depend on the source response; the current check timestamp can be retained in memory when persistence fails.

Evidence: [source loading and storage](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/service.js:161).

### 8. P2 — Sources can incorrectly display an Official badge

Use an empty or failed source whose URL is `https://example.test/stashapp.github.io/CommunityScripts/index.yml`. The Sources view labels it Official because its fallback checks for a substring anywhere in the URL. The existing `sourceTrust` helper correctly calls it unverified.

Use `sourceTrust(source.url)` consistently. This is a misleading provenance label, not evidence that package execution bypasses a security boundary.

Evidence: [source trust](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:934), [existing URL parser](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/core.js:198).

### 9. P2 — Installed refreshes can leave Browse's catalog stale

Visit Browse to populate its cache, return to Installed, then reload after a newly installed package appears in inventory. Returning to Browse reuses the cached list and can still offer that installed package for installation. Dependency installation from Installed is another path that changes inventory without refreshing an existing Browse cache.

Invalidate/reconcile the available-package cache whenever inventory or source membership changes, irrespective of the active tab. Also prune selections that no longer refer to available packages.

Evidence: [catalog cache](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:561), [post-operation refresh](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1114).

### 10. P2 — Normal operations make displayed install dates become Unknown

Mount the page and observe populated install dates. Run an operation that reloads inventory. The new package objects lack `installedAt`: `runOperation` never calls `recordInstallDates`, although mount and refresh do. Previously visible dates consequently become Unknown; new installs are not recorded on this path either.

Apply install-date reconciliation every time a new inventory is accepted. Existing first-seen timestamps should remain stable.

Evidence: [inventory replacement](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:1114), [refresh reconciliation](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:524).

### 11. P2 — Controller can retain a mounted flag after the SPA removes the UI

Mount successfully, remove the mounted root to simulate a host-page DOM replacement, then run controller sync. The controller still considers the app mounted and only calls `syncFromURL`; the enhanced UI is not remounted.

Check whether the app root is still connected before trusting the mounted flag. Add an integration case where the host replaces its settings subtree. The detached-root condition was reproduced; its frequency during real Stash navigation was not measured.

Evidence: [controller mount decision](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/controller.js:85).

### 12. P2 — Installed search omits the description actually displayed

Give an installed plugin a runtime description absent from package metadata. The card shows the runtime description, but searching a unique phrase from it returns no matches. `searchableText` only includes the package metadata description.

Include runtime descriptions in package search, ideally aligning search text with the description the user sees.

Evidence: [search fields](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/core.js:228), [displayed description](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:151).

### 13. P3 — Configuration search has the wrong visible and accessible label

Open Configuration. Its search box says **Search available plugins**. The shared toolbar labels every non-Installed tab as Browse.

Use a label per tab, such as **Search plugin configuration**, and a matching placeholder mentioning settings.

Evidence: [toolbar label](C:/Users/Ryan/Projects/stash-plugin-manager-enhanced/src/app.js:660).
